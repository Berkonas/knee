# Changelog

## 2.1.0 (2026-11-17)
- **Estimated loads are blocked without measured body metrics.** Until a participant's mass and height are entered, every force, moment, power, impulse and work value is *unavailable* and is left out of the time series and exports. Placeholder values (70 kg, 1.70 m) are no longer used.
- **Knee moment model corrected.** The quasi-static foot force now points from the centre of pressure toward the whole-body centre of mass instead of straight up. On real data the vertical force gave 2.9 N·m/kg, about twice the published stair-descent range (1.0–1.6 N·m/kg); the new default gives 1.5–1.8 N·m/kg. The vertical model remains available as an upper bound and is part of the sensitivity range. The exact equations are in `RESEARCH_PIPELINE.md`.
- New analytic tests: a force line through the knee gives zero moment, the COM model reduces to the vertical model when the COM is above the COP, and a hand-calculated tilted force.
- Dashboard groups: Joint kinematics, Movement and timing, Pole mechanics and Estimated loading, with category rows in the summary table.
- Video titles sit above each video instead of on the image. Angle labels and trajectories are off by default, and every overlay toggles independently. The plot legend has its own row and never covers data.
- Mode changes cross-fade in 160 ms. The fade is skipped when *Reduce motion* is on in TrailBuddy or in macOS.
- Per-recording validation report: `docs/VALIDATION_REPORT.md`, generated by `scripts/validation_report.py`.
- Packaged builds: macOS `.app` and `.dmg` with the pose models bundled (works offline), a Windows installer built on CI, and a headless `--acceptance <videos> <out>` check that runs import → pair → sync → track → calculate → export inside the packaged app.

## 2.0.1 (evaluation pass, 2026-11-17)
- Pole tips now extend through the dark ferrule. Before this fix, automatic tips sat about 28 px above hand-labelled tips on all 10 detected poles (median error 31 px).
- A pole shaft can no longer be assigned to both hands. When both hands pick the same shaft (common in the side view), the less confident hand is left empty. An earlier version re-searched for the hidden pole, and in validation it picked wrong lines 3 times. The minimum pole confidence is lowered to 0.15.
- Export no longer fails for front-only trials. Figures that need side-view data are skipped and listed in `figures_skipped.txt`. A new front-view figure is added.
- Analysis-interval input is validated: an end before the start is rejected with a message.
- At small window sizes, the plot selector is now a drop-down menu, the time label is compact, and the slider keeps a minimum width. The plot legend follows the light or dark theme.
- Time-series and summary CSVs are written with 9 significant digits, and a `frame_index` column links every sample to its video frame.
- New test checks that the exported CSV matches the in-memory result and that each timestamp falls exactly on a video frame.

## 2.0.0 (2026-11-16)
- Dataset import, audio pairing, RTMPose + YOLOX tracking, markerless pole detection, synchronised front and side workspace, and light/dark interface (see README and RESEARCH_PIPELINE.md).
